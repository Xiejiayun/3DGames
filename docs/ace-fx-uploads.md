# A8b · 飞行特效：只上传这一帧要画的粒子

烟尘、辉光各预留 428 个实例：420 个常规粒子加一次 8 枚热焰弹。保留容量可以避免飞行中反复分配，但容量不等于每次要传的数据量。每个实例有 9 个浮点数（36 字节）。现在只把当前层用到的连续前缀标记为需要更新；绘制前再次整理粒子时，以最后一次整理的长度为准。首次分配仍按完整容量进行，空层不绘制。

## 浏览器实际提交的字节数

对照为 `77ec1b1`。用同一脚本在 Windows Chromium 151.0.7922.34 / ANGLE SwiftShader、Three.js r160 上分别运行 WebGL 1 和 2；以下是两种上下文相同的读数。先画一次两层以分配缓冲，再观察真实 `bufferSubData` 调用，只统计这两层的六个实例属性；不是显存占用或总线实测。

| 一帧的负载（烟 / 光） | 原先 | 现在 | 特效绘制 / 三角形（前后一致） |
| --- | ---: | ---: | ---: |
| 1 / 0 | 15,408 B | 36 B | 1 / 2 |
| 5 / 3 | 30,816 B | 288 B | 2 / 16 |
| 100 / 100 | 30,816 B | 7,200 B | 2 / 400 |
| 两层变成 0 / 1 | 15,408 B | 36 B | 1 / 2 |
| 同一帧先准备 12 / 16，不画，再准备 0 / 2 | 15,408 B | 72 B | 1 / 4 |

| 0 / 428（满载再释放热焰弹） | 15,408 B | 15,408 B | 1 / 856 |

固定种子、同一座舱眼点的低画质爆炸截图，两版 PNG 字节相同。没有减粒子、换混合方式、改轨迹或关掉任何画面效果。

## 帧时间与重新出击

720×405、DPR 1、低画质、F-22X、随机种子 160。每个场景重新从机库出击，预热 36 帧，采样 72 帧；每次原生 `requestAnimationFrame` 驱动游戏的一次固定 1/60 s 步长，测量的是浏览器回调之间的**实际时间**，不是模拟时间。晴天巡航不生成粒子，爆炸段每 36 帧触发一次游戏里的大型爆炸，雷暴段用第三关原有闪电逻辑，每 36 帧触发一次。两版串行运行。

| 场景 | 原先 P50 / P95 | 现在 P50 / P95 | 场景 draw calls / 帧（前后相同） |
| --- | --- | --- | ---: |
| 持续巡航 | 216.7 / 433.3 ms | 216.6 / 416.6 ms | 63.8 |
| 爆炸密集段（峰值 110 粒子） | 250.1 / 616.7 ms | 233.3 / 450.0 ms | 72.0 |
| 雷暴（72 帧里 22 帧看得到闪电） | 183.3 / 350.0 ms | 183.3 / 350.0 ms | 68.5 |

爆炸之后通过暂停菜单连续三次「重新出击」，每次再飞 8 帧。两版三次均为 **61 个几何体 / 6 张纹理，0 个活跃粒子**。这是 `renderer.info.memory` 里已提交的对象数，不是显存字节。单次短窗口、软件渲染的 P95 有波动；能确定的是上传负载缩小，不据此宣称真机帧率提升或所有性能问题已消失。

复验：`node scripts/test-ace-fx-uploads.mjs`；加 `--profile` 记录三个场景和重开读数。设置 `ACE_SCREENSHOTS` 后，报告与固定画面写入其 `fx-uploads/` 子目录。默认 CI 断言每个属性的实际字节数、偏移、实例和 draw 数，不用帧时间作门槛。
